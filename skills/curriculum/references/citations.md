# 教材引用与注解协议 v1

课程讲解、计划说明、课后答疑和测验反馈引用教材时读取本文件。目标是让正文可以独立阅读，同时保留后续 Obsidian 插件定位原书所需的数据。课程档案、覆盖清单和单元卡中的审计定位仍按原格式保存。

## 正文写法

- 先讲清概念、推导或反馈，再把 `[^book-1]` 放在相关句子或段落末尾。正文不写惯常的“见原书 p. xx Figure x.x 与 p. xx”，不另起“依据：原书 pp. …”占用阅读空间。
- 一组连续句子说明同一个观点、引用同一位置时合用一个脚注。不同位置支持不同判断时分别标注；不把整章页码当作每个具体判断的依据，也不逐句堆脚注。
- 默认用自己的话解释。只有分析原文措辞、公式或原代码确实是学习任务时才在正文保留必要引文；例行反馈不用长引句代替解释。
- 引用数据必须来自已核实的课程档案与实际读过的源页。自编练习、补充解释不伪装成教材原文。未核实的页码、图号或引句不写入可跳转标注；说明具体疑点即可。
- 阅读任务本身要求打开某页、某图，或比较原文措辞时，可以在任务文字中说出该定位，并附脚注。普通讲解应说“交互闭环图”等有意义的名称。
- 不把单元卡的“教材依据”行照搬进正文，方括号也不能用于绕过脚注，例如 `[U001 的教材依据：C01 pp. 37–38。]`。附脚注后删掉同一来源的重复依据行、括号说明与来源标签。
- 选择题通常不需要在题面或选项中提示答案来源。来源放在回答后的反馈里；待答题面、脚注与隐藏元数据都不得包含答案键或泄露解题句。

每个助手回复、`quiz.explanation` 或其他独立呈现的工具文字字段使用自己的 `book-1`、`book-2` 等局部 ID，并在**同一个字段末尾**给出全部定义。不要只在下一条消息补定义，不要跨题面与反馈借用脚注。`book-` 是本协议的保留前缀；ID 只用小写英文字母、数字和连字符。普通个人脚注可用其他前缀。

输出前检查：除真正的阅读任务外，脚注定义之外没有页码／图号式出处；每个标记都有本字段的定义；链接与 JSON 指向相同文件和物理页；文字锚点已核实且不超过 120 个字符。

## 标注格式

使用标准 Markdown 命名脚注。定义为一行：可读链接之后紧跟一个 HTML 注释，注释里存严格 JSON，版本由 `textbook-ref:v1` 标识。不要把实际脚注包在代码块中。

以下例子来自当前教材已核实的交互闭环图：

```markdown
action 从 agent 发给 environment；reward 和 observation 从 environment 返回 agent。[^book-1]

[^book-1]: [原书·交互闭环图](<file:///E:/ZGerx/Tutorials/RL_Hands-On/Deep%20Reinforcement%20Learning%20Hands-On.pdf#page=33>) <!-- textbook-ref:v1 {"source_sha256":"57f1a10ebd8b705f7727442021981d1dad6f959f17624343bfe3090ef6900bc5","source_uri":"file:///E:/ZGerx/Tutorials/RL_Hands-On/Deep%20Reinforcement%20Learning%20Hands-On.pdf","pdf_page":33,"printed_page":"6","locator":"Figure 1.2"} -->
```

Obsidian 原生支持命名脚注，并将正文标记显示为编号；无定制插件时，读者仍可通过脚注查看来源链接。插件可以把 `book-` 脚注显示为注解标签，并读取隐藏数据。参见 [Obsidian 脚注语法](https://help.obsidian.md/syntax#Footnotes)。本协议只提供数据，不负责实现插件或阅读器跳转。

### JSON 字段

| 字段 | 必填 | 类型与含义 |
| --- | --- | --- |
| `source_sha256` | 是 | 课程 `course.md` 中的完整 64 位小写十六进制 PDF 指纹；用来区分版本、识别移动后的同一文件 |
| `source_uri` | 是 | 对应 `source_path` 的绝对 `file:` URI，不带 fragment；空格、中文、`#` 等按 URI 编码，不写 Windows 反斜杠路径 |
| `pdf_page` | 是 | 正整数，从封面起的 **PDF 物理页码**，第 1 页为 1；不使用印刷页码或零基索引 |
| `pdf_page_end` | 否 | 连续来源范围的末页，正整数且不小于 `pdf_page`；单页省略 |
| `printed_page` | 否 | 已逐处核实的印刷页码字符串，可为 `"6"`、`"vi"` 或 `"9–10"`；未知时省略 |
| `locator` | 否 | 已核实的图、公式、例题编号或小节标题，例如 `"Figure 1.2"`；供显示与页内定位 |
| `quote` | 否 | 源页中逐字核对、连续且能识别引用位置的短文本，最多 120 个字符；供插件在文本层中查找，不是助手概括 |

从课程档案读取指纹和文件位置，从源缓存的 `## PDF page N` 边界确认物理页码。印刷页码不能用全书统一偏移猜测。`pdf_page` 必须在课程的 `pdf_pages` 范围内；范围引用必须确认实际覆盖的内容。两处不连续的依据使用两个脚注，不能伪装成一个连续范围。

链接的 `#page=N` 与 JSON 的 `pdf_page` 必须一致，链接的文件 URI 与 `source_uri` 必须一致。脚注可读标签应简短，例如“原书·交互闭环图”或“原书·状态与观测”；长的书名、页码与引文不必再复制进标签。

JSON 单行、无尾逗号，不写 `undefined` 或未知值占位符。字符串中的引号、反斜杠按 JSON 转义；`<`、`>` 使用 `\u003c`、`\u003e`，连续的 `--` 使用 `\u002d\u002d`，避免结束或破坏 HTML 注释。解析后仍得到原始文字。不要添加未经核实的坐标、偏移量或伪造的精确位置。

`source_sha256` + `pdf_page` 提供版本明确的页级目标；`locator` / `quote` 提供页内查找线索。引用已读、提取可靠的文字时，必须填写可逐字核实的 `quote`；引用明确编号的图表、公式或例题时，必须填写 `locator`。只有提取不可靠、引用范围过宽或确实没有可核实线索时才省略，并保留页级定位。只有页码时，插件最多能保证定位到该页，不应声称已定位到页内具体词句。

`quote` 是查找锚点，英文通常选 6–12 个词即可，例如 `"The agent's communication with the environment is limited to reward"`；不要复制整条长句。输出前检查长度，超过 120 个字符就改选更短、仍能定位的连续片段。

## 转录与解析约定

`md-log` 在捕获每个事件时，把局部 `[^book-1]` 和其定义一起改成 `[^book-<事件完整 SHA-256>-1]`。这使整门课程的多次会话、题面与反馈即使重复使用局部编号也不会重名。事件重放产生相同 ID，不需要全局脚注计数器。

引用的正文与定义必须一起存在于原始消息中；转录只加命名空间，不猜出处、不补造缺失定义、不把旧的自然语言页码自动转换为引用。代码示例、普通个人脚注和 HTML 注释保持原样。`textbook-ref:v1` 的 JSON 不参与路径改写，不包含 `md-log` 管理标记。

后续插件的最小解析约定：

1. 在 Markdown 语法树中关联正文的 `book-` 脚注与定义，忽略代码中的示例。支持原始局部 ID 和转录后的 ID；ID 只是关联键，不能从 ID 推断文件与页码。
2. 从定义中读取 `<!-- textbook-ref:v1 {…} -->`，用 JSON 解析器读取字段。定义在问答 callout 中可能带有 `>` 前缀；按 Markdown 结构识别，而不是依赖固定行首。未知版本、缺字段或无效页码保留普通脚注显示，不猜跳转目标。
3. 用指纹确认教材版本，URI 提供当前文件位置，物理页码提供页级目标。插件若做页内查找，使用已核实的 `quote` / `locator`；不要把 `printed_page` 用作 PDF 索引。

本次变更从新生成的课程输出生效。`archive.md` 是扩展拥有的原本，外部笔记的同步区域有内容哈希；不要直接改写历史区域或重算哈希来绕过同步冲突。历史引用转换属于单独的迁移任务。
